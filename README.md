# Credit Risk Analytics Dashboard

**Predicting Serious Delinquency in Active Credit Accounts Using Behavioral Risk Analytics**

A Flask-based credit risk analytics application that predicts which active
credit accounts are likely to roll into 90+ Days Past Due (DPD) within the
next 6 months, built as an early-warning signal for proactive collections
outreach. Presented as a 25-slide interactive dashboard, with every number
computed live from the real dataset — nothing is hardcoded.

## What's here

- **Data**: a synthetic Indian consumer-lending credit-risk dataset
  (`Raw Data and Data Dictionary/`), 1.5M+ trade-month observations, with an
  unusually thorough data dictionary defining every variable's meaning,
  role, and leakage rules.
- **App**: `credit_risk_app/` — the Flask application, all 25 slides.
- **Roadmap**: `ROADMAP.md` — the full build history across 5 milestones,
  with real results and findings recorded at each step.
- **Reference doc**: `docs/variable_dictionary.md` — a standalone summary
  of the project scope, target, and variable dictionary.

## Setup

```bash
# 1. Pull the real data (only the mart this project needs, ~295MB)
git lfs install
git lfs pull --include="Raw Data and Data Dictionary/02_Data_Mart/behavior_risk_mart_part_*.csv"

# 2. Python environment
python3 -m venv .venv
source .venv/bin/activate        # macOS/Linux
# .venv\Scripts\activate.bat     # Windows cmd.exe
# .venv\Scripts\Activate.ps1     # Windows PowerShell
pip install -r credit_risk_app/requirements.txt

# 3. Prepare data, features, and models (run once, in order; ~5 min total)
python credit_risk_app/scripts/prepare_data.py      # raw CSVs -> Parquet + quality checks
python credit_risk_app/scripts/build_features.py    # behavioral (rolling/trend) features
python credit_risk_app/scripts/train_models.py      # trains all 4 models (~3 min)
python credit_risk_app/scripts/score_oot.py         # scores the OOT test set for Account 360 / Collections / Explainability

# 4. Run
python credit_risk_app/app.py                       # http://localhost:5000
```

All generated artifacts (`credit_risk_app/data/*.parquet`, `*.json`,
`credit_risk_app/models/*.pkl`) are gitignored — they're regenerated by the
scripts above, not committed.

## Architecture

```
credit_risk_app/
├── app.py, config.py
├── scripts/          # one-time data prep / feature engineering / training / scoring
├── services/          # business logic — one module per concern, no route touches raw data directly
├── routes/             # one Flask blueprint per nav slide
├── templates/         # one Jinja template per page, extending base.html
└── static/js, css/    # Plotly-based charts (bundled, no CDN dependency) + a shared design system
```

Each of the 25 sidebar slides is a normal server-rendered route — no SPA
framework — so every page is independently testable and no page depends on
client-side state from another.

## The model

Champion/challenger comparison of 4 models on an out-of-time split (never
random — see `ROADMAP.md` for why), on 37 features (18 base + 19 engineered
behavioral features):

| Model | OOT AUC | Gini | KS | Top-Decile Capture |
|---|---|---|---|---|
| Logistic Regression | 0.7122 | 0.4245 | 0.3025 | 24.6% |
| Decision Tree | 0.6978 | 0.3956 | 0.2921 | 22.5% |
| Random Forest | 0.7094 | 0.4189 | 0.2949 | 24.5% |
| **XGBoost (recommended)** | **0.7148** | **0.4296** | **0.3065** | **25.2%** |

See the app's own **Final Recommendation** and **Academic Interpretation**
pages for the full reasoning, and `ROADMAP.md` for the complete build
history, including two real bugs caught and fixed during development
(right-censored labels near the end of the data window, and a
percentile-vs-absolute-probability risk-banding issue caused by training
with balanced class weights).

## Scope note

This is a synthetic, case-study dataset (the data dictionary's own framing
includes fields like `how_students_should_use_it`), not live production
data. Treat every figure here as illustrative of methodology on realistic
data, not a real lender's portfolio.
